# VolcanoX ("Molten Ground") — Complete Project Description

A real-time volcanic eruption simulation written in C++17 and OpenGL 3.3 Core.

**Purpose of this document:** a single, accurate description of what is *currently implemented* in the project, written to be used as source material for the project report. It was produced by reading every source file and shader in the repository on 2026-10-11 and by running the program's own self-test and benchmark. Where the older documents (`PRD_MoltenGround.md`, `IMPLEMENTATION_GUIDE.md`) disagree with the code, this document follows the code (see §17).

**One-paragraph summary.** The scene is a night-time volcanic landscape: a 27-unit-tall volcano with a glowing crater that erupts in bursts (fire flash, smoke plume, shockwave rings, flying bombs with glowing trails, camera shake), five lava flows that creep down the slopes and one that fills a lava pool, burnt trees, a damaged hut, a windmill, a lake, a healthy forest, hills and distant mountains, a sky with stars, a moon and a storm layer that throws lightning. A 120-second automatic day/night cycle drives the sun and moon. Four vehicles (a pilot drone, a rover, a helicopter and a boat) can be driven from the keyboard, two more drones orbit on their own, and seven camera views are available. The lighting is a hand-written two-light Phong illumination model with selectable Flat, Gouraud and Phong shading, procedural textures, ray-traced shadows and reflections, and "inverse" ray tracing of the lava's glow into a light map. Everything is generated by code: no model, texture or sound file is loaded.

## 4. Architecture

### 4.1 Overall design principles

1. **Everything is procedural.** Meshes come from parametric formulas; textures from noise formulas; the HUD font from a 5×7 pixel table in code. Nothing is read from disk except the shader sources.
2. **A handful of reusable meshes.** Every object in the scene is assembled by transforming and drawing copies of the same ~20 meshes (`MeshLibrary`). Only the model matrix, colour and a few uniforms change per draw.
3. **Motion is mostly a closed-form function of time.** Drones, flames, rings, smoke, the windmill, the day/night clock and the eruption effects are computed directly from the simulated time `t` (and the list of burst start times), not stored as keyframes or baked animation. The only exceptions are the four keyboard-controlled vehicles, whose position depends on past key presses and is integrated every frame with `dt` (frame-rate independent).
4. **No scene graph.** Hierarchy is expressed by composing matrices in the draw functions (e.g. wheel = chassis × axle rotation).
5. **One shader program for the whole 3D scene**, switched between material behaviours by uniforms (`uMat`, `uTexId`, `uShadingMode`, …), plus one small program for the HUD.

### 4.2 Per-frame flow (`main()`)

1. Compute `dt` (clamped to 0.1 s). Advance simulated time `simTime` unless paused. Update the day/night lock easing.
2. Poll events, read held keys, apply any queued tessellation change (rebuild cone/pool meshes).
3. Update the four controllable objects (each gets live input only if it is the selected one; the others ease to a stop or hover).
4. Ease the orbit-camera target toward the controlled object (or back to the volcano).
5. Build the `Frame` (view/projection matrix, eye, sky state, lightning flash, which object to hide for the onboard camera). Apply camera shake.
6. Clear to the sky horizon colour (brightened by lightning), bind textures and the light map.
7. Rebuild the **ray-tracing proxy scene** from the current placement variables and upload it as uniforms.
8. **Render** (opaque pass, then translucent pass, see §4.3).
9. If light tracing is on, fire this frame's photons and update the light map (used next frame).
10. Draw the HUD (and the minimap if enabled). Swap buffers.

### 4.3 Render passes and ordering

OpenGL state set once: depth test on, back-face culling on (every mesh generator emits counter-clockwise-outward triangles), alpha blending `SRC_ALPHA, ONE_MINUS_SRC_ALPHA`.

**Opaque pass** (writes depth): sky dome, stars, moon, sun → terrain → volcano cone and crater bowl → crater glow disc → rim rocks → lava pool → five lava flows → lava droplets → rock chunks and bombs → burnt trees, hut, windmill → helipad → drones, rover, helicopter, boat.

**Translucent pass** (depth writes off, back to front): storm clouds, lightning bolts, eruption effects (shockwave rings, lake bombs, splash), ash puffs, eruption smoke, ash cloud. If the camera is *above* the storm layer (y > 62) the order of that group is reversed so the cloud layer, which is then nearest, is drawn last.

The object whose onboard camera is active is skipped so the camera is never inside its own body.

### 4.4 Mesh library

Each mesh is interleaved `x y z nx ny nz u v` (8 floats) uploaded once with `GL_STATIC_DRAW`. Triangle counts below are derived from the generator parameters in `SceneObjects.cpp`.

| Mesh | Parameters | Triangles |
|---|---|---:|
| cylinder | 16 segments, capped | 64 |
| cone | 16 segments, sharp tip, base cap | 48 |
| sphere | 10 latitude × 16 longitude | 288 |
| box | 1×1×1, 6 flat faces | 12 |
| disc | 24 segments | 24 |
| rock ×4 | jittered 5×7 sphere, seeds 1–4, jitter 0.4 | 56 each |
| volcano cone | open top, rim radius 0.14, **28 segments at the default level** | 84 |
| crater bowl | inward-facing frustum, 28 segments | 56 |
| pool disc | 24 segments at the default level | 24 |
| ring | inner 0.86, 64 segments | 128 |
| line / lightning bolt | `GL_LINES` | — |

### 4.5 Procedural geometry and normals (`Geometry.cpp`)

- **Normals** use vertex-normal averaging, `N_v = ΣN_i / ‖ΣN_i‖`, but only within a *smoothing group*, so a cone's side wall is smooth while its cap edge stays sharp and box faces stay flat.
- **Winding repair:** every triangle is compared with an "outward" reference direction and flipped if needed, so all meshes are counter-clockwise from outside and back-face culling is safe.
- **Rocks:** a coarse sphere whose vertices are pushed in/out by a hash of their *direction*, so shared vertices move together and the surface stays closed.
- **Lightning:** fractal midpoint displacement (each segment is split and the midpoint kicked sideways by a shrinking, hash-seeded amount); drawn as thin boxes because 1-pixel lines are unreliable in a core profile.
- **Determinism:** `hashNoise(int)` returns a repeatable value in [−1, 1], so every "random" placement is identical on every run.

### 4.6 Math library (`MathUtils.h`)

Column-major `Mat4` matching OpenGL. Rotation uses Rodrigues' formula. `perspective` and `lookAt` are written out explicitly. The normal matrix is the inverse-transpose of the model's upper 3×3 computed from cofactors, which is required because the scene uses non-uniform scales (flattened hills, the ground box, stretched clouds).

### 5.5 Lightning

A strike happens every 2.2 s with a quick double flicker (about 0.24 s). Each strike draws two fractal bolts from the storm layer (y = 62) to the ground at random angle and distance (22–62 units from the axis), chosen from 3 pre-built variants, and flashes the sky and clouds. **Lightning appears only at night:** it is suppressed once daylight ≥ 0.25.

## 6. Day/night cycle (`DayNight.h`)

- Closed-form clock: `hour(t) = fmod(20 + 24·t/120, 24)`. One full day lasts **120 s** and the program **starts at 20:00**, so the sun crosses the horizon at about 50 s (06:00), daylight reaches its maximum at about 55 s, and sunset is at about 110 s (18:00).
- Sun elevation `sin(2π(hour−6)/24)`; `daylight = smoothstep(−0.12, 0.25, elevation)`; `twilight` peaks at sunrise/sunset.
- Sun and moon travel on opposite great circles, tilted toward the default camera's forward direction so both cross the default view.
- **Key N** cycles *Auto → lock Day → lock Night*. A lock eases in over about 1.5 s so the sky never snaps. Locked day/night use fixed sun/moon directions (10:00 and 22:00).
- Everything that depends on the sky is blended from the same `daylight` value: sky gradient, stars, moon, sun disc, sky-light colour and direction, ambient colour, camera exposure, cloud brightness, lightning permission.

## 7. Eruption system (`Eruption.h`, `Effects.cpp`)

### 7.1 Burst schedule

The volcano erupts in **bursts**, not evenly.

- Scheduled burst *b* starts at `1.5 + 9·b` seconds.
- Envelope: linear rise over 0.35 s, then exponential decay with time constant 2.2 s.
- Amplitude 0.75–1.0 (hash), and **every third burst is "big" (+30%)**.
- **Key E** fires an extra big burst (amplitude 1.3) immediately; up to 8 fired bursts are kept.
- `intensity(t)` = sum of recent envelopes (capped at 1.5); `plume(t)` drives the ash umbrella; `shake(t)` drives the camera.

### 7.2 What reacts to a burst (all closed-form in time and burst start times)

Fire flash and smoke plume · crater point-light flare (`1 + 2.5·intensity`) · faster, harder lava droplets and rock chunks (up to 4× spawn rate) · shockwave rings · swelling ash umbrella · lake bombs (big bursts only) · camera shake.

### 7.3 Camera shake

A small rotation (X, Y, Z with different frequencies 63, 79, 51 rad/s) applied to the view matrix only, scaled by `0.011 × (Eruption::shake + rover bump)`. The eye position is unchanged so distances and the HUD stay correct. Key **J** turns it off.

### 7.4 Lake bombs and splash

After each big burst two bombs are thrown at random points on the lake (≈ 140 units away). The launch speed is **solved** so each lands on its target: with horizontal distance *D*, elevation θ, launch height *h₀* and water level *h_w*, `T = √(2(h₀ − h_w + D·tanθ)/g)` and `v = D/(T cosθ)`. In flight each bomb is a tumbling white-hot rock with a 16-puff glowing trail. On impact: a flash of fire, 4 expanding ripples, 12 spray droplets (each makes a small ripple where it falls back) and 7 rising steam puffs.

## 8. Lighting and shading

### 8.1 Illumination equation (`lighting.glsl`)

```
I = I_e                                                   (emission: lava, glow, hot rocks)
  + k_a · I_a                                             (ambient)
  + Σ over lights  f_att(d) · [ k_d · I_d · max(0, N·L)   (diffuse)
                              + k_s · I_s · max(0, R·V)^n_s ]   (specular)
R = reflect(−L, N)   (Blinn–Phong option uses (N·H)^n_s, H = normalize(L+V))
```

The result is returned as separate diffuse+ambient and specular vectors so a texture can modulate only the albedo part, never the highlight or the emission.

### 8.2 The two lights

| | Light 0 — crater glow | Light 1 — sky light |
|---|---|---|
| Type | Point light hovering 6 units above the vent, at about (0, 31.1, 0) | Directional |
| Source | The lava fountain | Moon at night, sun by day (blended by daylight so it never snaps) |
| Diffuse | (1.0, 0.45, 0.15) warm orange | night (0.12, 0.14, 0.20) → day (1.0, 0.95, 0.82); warmer at twilight |
| Specular | (1.0, 0.6, 0.3) | night (0.15, 0.16, 0.18) → day (0.60, 0.60, 0.55) |
| Attenuation | `1/(1 + 0.06 d + 0.02 d²)` (radial) | none |
| Extra | × `(1 + 2.5·eruption intensity)` flare | — |
| Ambient (global) | night (0.08, 0.09, 0.14) → day (0.55, 0.62, 0.78) | |

The crater light is placed *above* the vent, because exactly at the vent it would lie on the cone's tangent plane and light none of the steep slopes. A camera **exposure** (9 at night, 4 by day) brightens the lit result, since the scene's albedos are dark.

### 8.3 Materials

| Material | k_a/k_d ratio | k_s | Shininess n_s | Emission | Used for |
|---|---:|---|---:|---|---|
| Matte (default) | 0.20 | 0.05 | 4 | none | terrain, trees, vehicles |
| Rock | 0.20 | 0.05 | 4 | none | volcano, rocks, mountains |
| Lava | 0.33 | (0.95, 0.85, 0.60) | **140** | yes (0.3–1.0 per layer) | flows, pool, crater disc, droplets |
| Ash | 0.23 | 0.05 | 2 | puffs only | smoke, ash |
| Unlit | — | — | — | colour as is | sky, stars, lightning, clouds, rings |

Lava's exposure is scaled down on its diffuse part so the sun does not wash it out, while its glossy highlight keeps most of the exposure.

### 8.4 Shading modes (keys 1 / 2 / 3)

| Key | Mode | Where lighting is computed | Notes |
|---|---|---|---|
| 1 | **Flat** | Per fragment, with one normal per triangle from `normalize(cross(dFdx(P), dFdy(P)))` | Visible facets; Mach banding on the cone at low tessellation |
| 2 | **Gouraud** | **Vertex shader** runs the whole equation; the rasteriser interpolates the intensities | Specular highlight is smeared/hard-edged on large triangles. With ray tracing on, Gouraud falls back to per-fragment lighting because shadows need a per-pixel position. |
| 3 | **Phong** (default) | Fragment shader, interpolated normal | Smooth round highlight |

Other related switches: **L** cycles lights (both / crater only / sky only), **K** cycles terms (ambient / +diffuse / specular only / full), **B** toggles Phong vs Blinn–Phong specular, **+ / −** change tessellation (cone: 4, 6, 8, 12, 16, **28**, 48 segments; pool disc: 3, 4, 6, 8, 12, **24**, 48), which together make the Flat/Gouraud/Phong differences easy to demonstrate.

### 8.5 Procedural textures (`Texture.cpp`, key T)

Three 256×256 RGB textures generated at start-up from tileable value noise (hash lattice, smoothstep blend, fractal Brownian motion), uploaded with mipmaps and `GL_REPEAT`:

| Texture | Construction | Used on |
|---|---|---|
| Rock | 5-octave fBm + thin dark ridged "crack" lines (`ridge⁶`), cool grey-brown | Volcano, rim rocks, rock chunks, mountains |
| Ash | fine 3-octave noise + low-contrast blotches, neutral grey | Terrain |
| Wood | stripes along *u* bent by noise + fibre noise, warm brown | Burnt trees |

The texel mean is ≈ 0.5 and the shader multiplies albedo by `2·texel`, so the average colour is unchanged by switching textures on or off.

## 9. Ray tracing (Phase 3)

OpenGL 3.3 has no compute shaders and GLSL has no recursion, so this is a **hybrid**: the raster pipeline draws the picture and rays are cast per fragment against a small analytic **proxy scene** to depth 1. The proxy scene is never drawn; it is rebuilt every frame from the same placement variables as the drawing code, so shadows always match what is on screen.

### 9.1 Proxy scene (`RayScene.h`, uploaded as uniforms)

| Shape | Count | Stands in for |
|---|---:|---|
| Cone / cylinder (tilt about Z supported) | up to 8 | volcano (index 0), 6 burnt trees (sharp cones, leaning −10°), windmill tower (cylinder) |
| Sphere | up to 4 | 2 orbiting drones, pilot drone, helicopter body |
| Oriented box (yaw about Y) | up to 3 | hut, rover, boat |
| Ground plane y = 0 | 1 | terrain |

Intersection formulas are the same in C++ (`RayScene.h`) and GLSL (`raytrace.glsl`): quadratic for the cone/sphere, slab test in the box's local frame, plane test.

### 9.2 Modes (key R: off → shadows → shadows + reflections)

- **Shadows:** one shadow ray per light from just above the surface. The volcano does not shadow the crater light (that light sits inside the cone), and receivers on the cone skip the cone as an occluder to avoid self-shadowing. Ambient is never shadowed.
- **Reflections:** one bounce, on the **lake** (Schlick Fresnel, F₀ = 0.02) and weakly on **lava** (constant 0.12). A reflected ray that hits a proxy shape is shaded cheaply (ambient + sky light, no shadow ray, no second bounce); a miss returns the analytic sky including the sun and moon discs.
- Only fragments within 400 units of the axis are traced.

### 9.3 Inverse (light-ray) tracing of the lava glow (`PhotonMap.h`, key F)

- Camera-ray tracing asks "what does this pixel see?". This asks the opposite: every frame **4,096 photons** are fired from the lava and traced through the same proxy scene on the CPU.
- **Emitters:** 16 samples along each of the 5 flows (positions on the advanced part of the flow, power ∝ area × (0.4 + heat)), plus up to 24 flying droplets (emit over the full sphere).
- **Sampling:** photons are assigned to emitters in proportion to power (stratified, deterministic); flow samples emit cosine-weighted over the hemisphere, droplets uniformly over the sphere.
- A photon that lands on the **ground or the volcano slope** is deposited (bilinear splat) into a **128 × 128 light map** (RGB16F texture covering ±160 units); a photon that hits a tree, the hut, the windmill, a vehicle or a drone is *absorbed*, which leaves shadow-shaped gaps.
- The map is temporally smoothed (new frame weight 0.15) and read by the terrain/object shader as **extra diffuse light** scaled by a gain (default 3).
- Attenuation comes out of the geometry (photon density falls as 1/d²), not from a formula.
- **Key M** shows the light map as a 200 × 200 top-down minimap (volcano at the centre) with a hit count.

## 10. Transformations and hierarchical motion

All transformations are composed from `Mat4::translate/rotate/scale`, always in the order *translate × rotate × scale* for an object, with child objects multiplying onto their parent's matrix.

| Object | Hierarchy |
|---|---|
| Drone | root = T(position) · R_y(heading) · R_x(pitch) · R_z(roll); arms, hubs, propellers and the gimbal camera are children; propellers spin R_y(ωt) with alternating direction |
| Rover | chassis · cabin, windscreen, mast, dish, headlights; four wheels are children that also rotate about their axle by `distance / radius`; bump pitch/roll/hop |
| Helicopter | fuselage, canopy, tail boom, fin, skids on struts; main rotor spins R_y(angle); tail rotor spins about X at 1.6× |
| Boat | hull, bow, cabin, mast; radar bar spins R_y(2.5t); heave/pitch/roll as sines of time; V-shaped wake that grows with speed |
| Windmill | nacelle child of tower; rotor child of nacelle; each blade R_z(spin + 90°·i) · R_x(droop) |
| Rim rocks | ring of rocks is a child of the crater transform |
| Burnt tree | trunk, branches and debris share the tree's lean/rotation parent |
| Flying rocks and droplets | translate (ballistic position) · rotate (about a hashed axis) · scale (shrink/size) |

### 12.1 Rover collision (`Controller.h`, `Collider.h`)

- The rover is a circle (radius 1.5). Every obstacle is a circle on the ground plane built from the **same numbers the draw functions use**, so a collider is always where its object is drawn: burnt trees and their debris, the hut (3 circles + debris), the windmill footing, the ~90 forest trees, the volcano footprint (radius 19.5), landed rock chunks (rebuilt every frame), a *parked* helicopter, the lake (ellipse 31 × 21), and the edge of the world (radius 150).
- On overlap it is pushed out; velocity is reflected with restitution 0.35 (head-on hit returns at 0.35 v, glancing hit slides); the impact speed drives damped springs for nose dive/lift, roll and a hop, kicks the yaw on a glancing blow, and shakes the camera (only when driving it or looking through it).
- Impact below 1.2 units/s is a scrape, not a bump; a bump within 0.25 s of the last is not counted again. The HUD shows `BUMPS n (WHAT)`.
- There is **no physics engine**: collision is a single distance comparison per obstacle.

## 16. Design decisions worth explaining in the report

1. **Own math library instead of GLM** — environment-driven, but also makes every transform explainable line by line.
2. **Hybrid ray tracing** — rays in the fragment shader against about a dozen analytic shapes, because OpenGL 3.3 has no compute shaders and GLSL has no recursion; depth 1 only.
3. **Inverse tracing on the CPU into a 2-D light map** — avoids per-pixel light-source loops, gives shadow-shaped gaps for free, and attenuation emerges from photon density.
4. **Closed-form animation** — position, size, colour and alpha of every effect are functions of age or time, so nothing is stored, baked or pre-recorded and pausing is free.
5. **One mesh library, many instances** — few unique meshes; per-draw uniforms select colour, material, texture and emission.
6. **Smoothing groups for normals** — correct smooth/sharp edges from a single normal-averaging routine.
7. **Crater light lifted above the vent** — avoids a degenerate tangent-plane light that would leave the slopes dark.
8. **Lava pool tied to a flow** — a free-standing pool looked like a flat orange disc; making it fill only after the sheet flow arrives reads as physical.
9. **Colliders built from placement data** — one source of truth for drawing, shadows and collision.
10. **Orbit camera, no cursor capture** — avoids focus/capture failures during a demonstration; mouse drag orbits instead.
11. **Translucent objects after opaque, no depth writes** — prevents earlier puffs hiding later ones and vehicles painting over clouds.

## 17. Limitations, unused code and documentation drift

### 17.1 Known limitations (honest list)

- **Shadows and reflections come from proxy shapes**, not the real meshes: the rover and boat are boxes, the drones/helicopter are spheres, trees are cones. Shadows of the flow slabs, rim rocks, rocks and particles do not exist. At most 8 cones, 4 spheres, 3 boxes.
- **One reflection bounce**; the reflected scene is shaded cheaply (no shadows in reflections).
- **Ray tracing is only per fragment within 400 units** and is the dominant cost (≈ 188 → 48 FPS here).
- **~1,170 draw calls per frame, not instanced** (rim rocks, flow segments, clouds, forest trees are separate draws).
- **No shadow mapping, no cube-map reflections, no soft shadows, no bloom/HDR post-processing, no audio, no save/load.**
- Gouraud mode silently becomes per-fragment lighting while ray tracing is on.
- Colliders are circles on the ground plane; flying vehicles collide with nothing (only altitude/radius limits).
- Photon deposits are only onto the ground and the volcano slope; the map covers ±160 units at 128×128 cells (2.5-unit cells).
- Textures are generated at start-up (a short one-time cost) and are 256×256.
- Time of day is a fixed 120-second cycle and always starts at 20:00.

### 17.2 Unused code still in the files

`drawGroundPlane` and `drawLavaFlowChannel` (SceneObjects.cpp) are declared and defined but **not called**; the `line` and `lightningBolt[]` meshes are uploaded but the bolts are actually drawn from their polylines as boxes. They are harmless leftovers from earlier stages.
